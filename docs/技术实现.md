## 零、先说清楚这东西是什么形状

```
┌─────────────┐   MCP (streamable-http)   ┌──────────────────┐
│  你的 AI    │ ────────────────────────► │   Loci (Python)  │
│  客户端      │  七个工具                  │   一个容器         │
└─────────────┘                            └────────┬─────────┘
      ▲                                             │
      │  可选：网关往对话里插东西                      │  读写
      │                                             ▼
┌─────┴────────┐                          ┌──────────────────┐
│  mini gateway│ ── HTTP ────────────────► │  buckets/  你的盘 │
└──────────────┘                           │  一条记忆 = 一个 │
                                           │  .md 文件（明文）│
                                           └──────────────────┘
```

**记忆的载体是 Markdown 文件，不是数据库。** 一条记忆一个 `.md`：YAML frontmatter 放元数据，
正文放原话。SQLite 只用来做**索引**（向量、BM25、投影），删了能从 `.md` 重建 —— 反过来不行。

这条选择决定了后面所有事：你随时能用文本编辑器打开自己的记忆，也能 grep、能同步、能备份。
系统坏了，记忆还在。

**核心只做一件事：提供能力。** 什么时候用、要不要用，永远在调用方。
所以「怎么把提醒递到眼前」不在核心里，在网关那层 —— 核心只回答「现在该不该提醒」。

## 一、写入

### 三个维度分别落在哪

| 维度 | 落在哪 | 怎么写 |
|---|---|---|
| **纵向 event / mind** | frontmatter 的 `room`，四个值锁死 | 写的时候必须自己填，填错**当场拒绝**，没有兜底 |
| **横向 过去 / 未来** | `tense` 字段（空 = 过去，`want` = 未来朝向）+ `when` | 见第四节 |
| **第三维 场景锚点** | `tags`（场景词）· `subjects`（主体）· `aliases`（引申词） | 打标模型抽，但受**字面校验**约束 |

四间房：

```
EVENT/SELF    亲历的          MIND/TRAITS   我是什么样的人
EVENT/WORLD   听说、看到的      MIND/VIEWS    我怎么看一件事
```

判法只有两问：这事我在不在场；这句在说人还是在说我怎么看一件事。
**房间不给猜。** 参数校验层直接拒并列出四个选项 —— 一个能被兜底的约束等于没有约束。

### 第三维的三类标签，写法不一样

- **`tags`（场景锚点）**：模型抽完之后，代码逐个校验「这个词是不是**逐字出现在原文里**」，
  不在就丢掉。所以标签永远是原文里真有的词，不是模型的联想。
- **`aliases`（引申词）**：近义词、上位词、可能换个说法去搜的词。**只喂给 BM25**，不上脸、不进正文。
  它解决的是「我当时写『不理智』，三个月后想搜『失控』」。
- **`subjects`（主体）**：这段话里出现了哪些人。两道确定性的闸：
  ① **代词不进**（我/你/他/她/我们/自己/对方…）—— 指代不是名字，指代的解析要么确定要么不做；
  ② **过别名表归一** —— 「老张」和「张三」不归一就会分裂成两个人，检索当场断掉。
  别名表是手工维护的 YAML，放在数据卷里，**不给模型写**。

### v/a 是自己打的，不是模型判的

每条记忆带 `valence`（愉悦度）和 `arousal`（唤起度），0~1，**写入时必填，缺了直接拒**。

为什么不让模型判：**遗忘公式吃这两个值**（第六节）。模型猜的情绪如果能决定什么被忘掉，
那这就不是「我的记忆」了。这一条是整套东西的地基，不是风格偏好。

### 正文逐字落盘

进库的正文一个字不改写、不压缩、不归纳。摘要、标签、主体是**另外的字段**，后台回填，
跟正文分开放。「远的只给摘要」是**显示层**的事，盘上永远是原话。

## 二、想起

### 1. 主动回忆：`recall`

四个筛子可以叠：`when`（时间）/ `room`（房间）/ `tag`（标签）/ `query`（扔词搜）。

**分岔只有一处：有没有 `query`。**

**没有 `query` = 在浏览。** 走梯度视图：近三天逐条清晰，更远的塌成「前段时间 + 2~3 条代表」。
这条路故意**不给**久没被想起的记忆冒头的机会 —— 「我不去找它也会出现」是活着的记忆的待遇。

**有 `query` = 在找。** 检索是**三路混合**：

```
向量（本地 embedding，语义）
  ＋ BM25（关键词，中文分词后建索引，aliases 也喂进来）
  ＋ 字面命中加权
      ↓
  过分数线 → 按时间排、每条带分数
      ↓
  线以下不丢，折叠成一行：多少条 · 最高几分 · 最早那条讲什么
```

**「挡了什么」是看得见的** —— 这比默默丢掉重要：你能立刻判断是词没搜对，还是真没有。

另一条路是 `view="画面"`：按共享的场景词把命中的记忆聚成簇，代表条下面挂从属画面，
看的是「这件事怎么一路走过来的」。它跟默认视图是同一批数据的两种摆法，不是两套检索。

### 2. 辅助回忆：网关那一层

**核心不主动说话**（MCP 是被动协议，工具没被调用就没有它的份）。所以辅助回忆放在网关：

**强信号**：用户这句话里出现「记得 / 上次 / 之前 / 想要」这类词
→ 拿整句去 Loci 跑一次检索 → 过 **50 分线**（可配）→ 在**最新一条用户消息之后**插一行：

```
〔记忆提醒〕和这句有关：事件 3 条 · 认知 1 条
```

**弱信号**：出现场景词，走同一条路，闸更严。

三个刻意的设计：

1. **只报数量，不报内容。** 给摘要 = 系统替他想起来了，他会顺着那段摘要往下说；
   给数量 = 拍他一下，**要不要真的去看是他的判断**。
2. **贴在最新用户消息之后**，不贴在系统提示里 —— 注意力在末端，而且不动前面的 prompt 缓存前缀。
3. **每轮现算，不累积。** 0 条就一个字都不说。

插入的位置是「出锅前的最后一步」，绕开了消息流水线上所有会吃掉或搬走它的环节。

### 3.补充：被管理过的event和mind如何被想起

这一节回答一个具体问题：**记忆被「收起来」之后，翻的时候还看不看得见。**
两种收法，长相完全不同 —— 而这个不同**就是 event 和 mind 的差别**。

**时期（一段日子有了名字）—— 名字冒出来，记忆一条不少：**

```
〔when=2026-08-15〕4 条 · 新→旧
◈ 那阵子在…………  2026-xx-xx..2026-xx-xx  ▏盖着这里 n 条
  15:41  xxxxxxxxxxxxxxxx                    (2750..)
  14:19  xxxxxxxxxxxxxxxx                    (cd6c..)
  13:58  xxxxxxxxxxxxxxxx                    (35a7..)
  12:51  xxxxxxxxxxxxxxxx                    (bfd1..)
```

**一行都没被压掉。** 时期只落「名字 + 范围」，**一条记忆都不压住**：
谁在这段日子里是**按日期现场算**的 —— 所以后来补记的事会自动归队，
时期之间也可以交叉、可以嵌套。

**认知快照（几条讲同一件事）—— 反过来，那句话顶上来，底下的收进去：**

```
▣ 我…………  ▏盖着这里 3 条
```

被点名的那 3 条**不再单独占行**。但它们**没有死**：`query` 照样搜得到，
拿这个快照的 id 直查，会把它盖着的每一条逐字列出来。

**为什么两种收法不一样**（这是设计，不是实现细节）：

| | 时期（event） | 快照（mind） |
|---|---|---|
| 在做的事 | **给一段日子取名** | **把几条想法浓缩成一句** |
| 成员怎么定 | 日期落在范围里，**现场算** | 我**点名**，写死 |
| 被收的记忆 | **照常独立冒头** | 不再独立冒头 |
| 为什么 | 事情发生过就是发生过，取名不该让它消失 | 想通了之后，那三条散着的话就该让位给那一句 |

## 三、呼吸（`breath`）

开口之前调一次，返回**一屏**，四块：

| 块 | 放什么 | 判据 |
|---|---|---|
| **档案** | 名字、称呼、**钉着的准则** | 「来不及去搜的才留在门口」 |
| **提醒** | 未来 30 天内有日期的事，越近越大声 | 见第四节 |
| **中期** | 最近三天塌成一张卡 | 说人话，不给机器读数 |
| **忽然想起** | 随机 1~2 条 | 纯随机，不做相关性 |

`pin`（钉成准则）有一道**形状校验**：只接受祈使句（我要 / 我不 / 先…再 / 别… / 每次…）。
描述句钉不上去 —— 因为把「我总是心急」钉成准则，语义会变成「我要犯这个错」。

**这一屏里所有的字，要么是存的时候写下的原话，要么是模板里的死字，不过模型。**
说人话是**壳**：把「EVENT 60% / MIND 40%」翻译成「做的和想的一半一半」是模板拼的，
记忆正文一个字不动。

📌 **梦不在这一屏里**。它走另一条路（第五节）。

## 四、有关未来

未来朝向不是一个工具，是一个字段：`tense="want"`，可选 `weight`（压在心头多重）。

**同一个 `when` 字段，三种填法 = 三种钟，不加类型字段：**

| 填法 | 例子 | 怎么催 |
|---|---|---|
| **有期限** | `when="2026-09-01"` | 日子越近声音越大 |
| **有量级** | `when="3w"` / `"10d"` / `"2m"` | 催法 = 挂了多少天 ÷ 这个量级 |
| **等触发** | 不填，条件写在正文里（「等他回来」） | **永远不催**。条件成立要靠自己认出来 |

三类都**不做「超过 N 天自动结案」**。想放下、不做了，永远是自己 `trace(status=...)` 点头的那一下。
一个会自动关掉的愿望，等于没许过。

在呼吸里的呈现是**问句**不是陈述：「挂了 11 天（重 0.9）：…… 这条还算数吗？」——
陈述句会被读成背景音，问句才要求回答。

## 五、记忆库半自动化管理

这一节三件事共用**同一副骨架**：定一条规则，跑三个实例。

```
攒着的东西 → 过阈值？ → 是 → 摆出来 / 织出来 → 交给人判断
                       └ 否 → 闭嘴
```

### 1. 发呆（`muse`）：找出哪几条在讲同一件事

**只指不写。** 它把「这几条可能是一回事」摆到面前，然后闭嘴 —— 那句归纳永远是人自己落笔。

判据总纲：**不许只凭猜指东西，每一指后面都要跟着人自己留下的痕迹。**
所以证据按**硬度**排三层，不是按相似度：

```
① v/a 邻域分架   ← 自己亲手打的坐标，最能代表「这些事对我是同一类」
② 架内 from 链   ← 自己亲手连的来源链，最硬
③ 架内语义相似   ← 向量只配当海选（相似度线 0.76；0.70 会把半个月串成一团）
```

**时间不参与** —— 认知不认日历。

事件那边找的是另一种东西（「哪段日子还没有名字」），三种指法都带证据：
**词爆发**（某个场景词在一段日子里密集出现、窗外稀疏 = 一段日子的形状）·
**成分漂移**（相邻时间窗的向量质心跳了大步 —— 只提边界，不画段）·
**空白记账**（有地图之后，新过完的一段没被盖住）。

两道闸：**冷却期**（刚写下的不参与）·**「还在发生的事不提」**（说不出它是什么的时候别指）。

#### 摆出来之后，我做什么 —— 这条链路

发呆到「摆出来」为止。**后面每一步都是ta自己动手**，而且 event 和 mind 走的是两条路：

```
muse 摆出来
   ├── 事件那边：这段日子还没有名字
   │      → 我给它取个名 → fold(when=起..止)  = 立一个「时期」
   │      → 记忆一条不压，名字只是盖在上面
   │
   └── 认知那边：这几条在讲同一件事
          → 我先判断：这几条说的东西，我现在还认不认
          → 认  → 浓缩成一句我自己写的话 → fold(folds=[ids])
          → 不认 → 不浓缩。这几条是我想岔了的证据，留着比收起来有用
          → 想法变了 → regrow 换新版（旧版留档，演变史自己就有了）
```

**关键的一步在「不认」那一支。** 系统不会替我判断哪条该留哪条该收 ——
一堆讲同一件事的旧认知，可能是「我想明白了，该收」，也可能是
「我以前一直这么错，这堆错法本身就是我要看见的东西」。
**这两种在向量空间里长得一模一样**，只有本人分得出。

##### 最后一步：哪些该钉成准则

浓缩完，从里面挑出**要变成行动的**那几条，`pin` 住。钉住的东西会进「呼吸」的第一屏 ——
也就是每次开口之前都会看见的那几行。

**`pin` 有一道代码强制的形状校验：只收祈使句。**

```
✗ 描述：我总是在验收的时候心急。          ← 钉不上去，当场拒绝并给改写例
✓ 朝向：我要先跑完全套再报结果。
```

为什么要这道闸：**把缺点钉成准则，语义就变成了「我要犯这个错」。**
描述句读一百遍也不会变成行动，而第一屏的位置很贵。

什么情况该钉（这一层是判断，代码不强制）：

**这些可以自己去和他做调试。什么该钉，尽量是一些在开口之前必须要知道的东西，例如行为准则等。**

### 2. 做梦

**原料**：压在心头的 + 想不明白的。**不是所有记忆都进梦池 —— 已经被想明白（写成 mind）的不进。**
所以「消化」这个动作本身就在决定梦见什么。

**判据**（真数据上拍的）：

```
dull_line     0.35   一条的分量低于它，一分都不算
pressure_line 0.65   最重的那一条过线才织（不是相加）
per_day       1      一夜一梦
```

用「最重的那一条」而不是求和，是因为求和会让平淡的日子靠条数堆出一个梦来。

**生命周期 —— 这是梦唯一特别的地方：它会自己消失。**

```
夜里织好（300~600 字完整版）
   │
   ├─ 真夜间（用户 3~4 小时没说话）→ 完整版落盘存活，递整版
   │
   └─ 用户回来的第二条消息 → 触发降级
         ↓
      碎片层（30 分钟 / 15 轮，谁先到算谁）
         ↓
      只剩一句（60 分钟 / 30 轮）
         ↓
      删掉，只留一条痕迹
```

想留住只有一条路：**当轮把它 `grow` 成记忆** —— 写下来那一刻它就不是梦了。

噩梦有单独的闸（v < 0.3 且 a > 0.7），过线才允许出声说「我做噩梦了」。线定得严是有意的。

🔴 **梦是整套里唯一需要「删掉」的东西，也是唯一挑客户端的功能。**
它需要一个**能管理上下文的网关** —— 能往里放，也能拿走。
只能靠 hook 注入的客户端（注入是只增不减的）做不了梦：一个永远掉不下去的梦，
第二天还在上下文里躺着，那就不是梦了。**其余功能 hook 都能实现。**

### 3. 收窗压缩（可选）

一天快结束时提醒写入记忆、压缩当天对话；第二天只保留压缩过的 + 最近 N 个来回（可配）。
这块刻意做成**独立文件、按需自取**：单窗口聊到底的人和经常换窗的人要的不是一个东西，
所以「什么算新窗口」永远是宿主递进来的信号，核心不假设。

## 六、关于遗忘

遗忘是**渐进**的，分三档，而且**一个字都不删**：

```
alive  ─────► faded ─────► sunk
       撑不住了      更久了
```

- **faded**：**浏览时不再冒头**（「我不去找它也会出现」这条待遇没有了），但**搜得到**，分数打折
- **sunk**：正文换成摘要，**原文搬进存档文件**，向量不动 —— 所以还搜得到，只是够到的是摘要
- **捞回来**：`trace(restore=True)`，原文从存档读回，并且**算一次真的想起**

撑住多久，公式是：

```
撑住天数 = 基准天数 × 情绪系数（自己打的 v/a 算出来的）× [结案的对折]
          faded 基准 45 天 · sunk 基准 180 天
```

分子是「多久没被想起」—— 每一次真的想起都会把它清零。

**刻意没有的东西：次数系数。** 早期版本里「被想起的次数」也参与计算，后来整个删掉了。
理由是自动统计（次数）和人工判断（v/a）在同一个乘式里，等于让统计去覆盖判断；
而「被提得多的」不等于「最真的」。**常被想起的不沉**这件事没丢 —— 想起会刷新时间，
那是第一重，也够用了。

## 七、边界：说清楚做不到什么

- **梦挑客户端**（上面说了）。其余功能只要有 hook 都能做。
- **默认没有 API 鉴权。** 端口默认只绑本机。要开到公网，请自己在前面放一层反代 + 鉴权。
- **向量建议放本地**（ollama 之类）。走远程 API 意味着每次检索都花钱、都走网络；
  辅助回忆是每轮都可能跑的，那个成本会很难看。
- **打标依赖一个外部模型**（任意 OpenAI 兼容 API）。它不可用的时候，记忆照常落盘，
  只是没有标签和摘要 —— **降级路径是「少点东西」，不是「写不进去」**。
