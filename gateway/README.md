# mini gateway —— **系统主动说话的那条路**

🔴 **没有这一层，整套东西少掉将近一半。**

理由很硬：MCP 工具面是「AI 自己伸手」，系统在那条路上**一个字都插不进去**。
而有三样东西的性质就是「系统主动说一句」——

### 必选的两样（不接就少掉一半）

| | 什么时候 | 说什么 | 贴哪儿 |
|---|---|---|---|
| **相关记忆提醒**<br>`自动贴.js` | 你说到「上次 / 还记得 / 之前」这类词（强档），或者这句话有实质内容（弱档） | 「有几条相关记忆」 | **真尾巴**（离模型开口最近） |
| **戳戳送达**<br>`戳戳送达.js` | 你很久没说话之后回来的第一句 | 昨夜织的那个梦 · 「攒了 N 团没整理的」 | 稳定前缀区 |

**都只报有什么、报几条，不报记忆正文。** 要不要去看，判断权留给 AI 自己。

### 可选的一样

| | 是什么 | 开关 |
|---|---|---|
| **近期记忆视图**<br>`近期记忆视图.js` | 隔天开窗的时候，把「昨天做了什么」贴进去 | `LOCI_RECENT_VIEW=1` |

⚠️ **这一样只做了一半，代码里留着口子，另一半得你自己接。** 说清楚是哪一半：

```
✅ 已经有的   recall(when="昨天") 的原文摘录（前 20 行，可配）
              开窗算一次、同窗口内不重算、一个字不落盘
❌ 还没有的   把昨天压成 2-4 句「情景记忆」（保留感受 + 保留一定原文）
```

`算一次()` 有个参数叫 `生成摘要`，是**留给你传的回调**：

```js
const 摘要 = typeof 生成摘要 === "function" ? await 生成摘要(原文, 摘要句数) : null;
```

不传 = 纯原文摘录。传了 = 摘要贴在原文摘录上面。

### 🔴 那 2-4 句该由谁写 —— 这一条最容易做错

**不要丢给一个外部模型去写。** 让 deepseek/GPT 读一遍昨天的记录再总结，
写出来的是**新闻稿**：事情对，人不对，感受全没了。

**正解是：由活过那个窗口的 AI，在收窗那一刻顺手写。**
它当时就在场，写「昨天」对它来说不是总结，是回忆。

配套的时机就是下面这个 —— **看 token 数**：

| 门 | 干什么 |
|---|---|
| **150k** | 知道一声，什么都不干，接着聊 |
| **175k** | 盯话题边界，聊完这段就存 |
| **190k** | 下一个来回就砍 |
| 🔴 **192k** | 硬砍。留 8k 是因为写摘要 + 存记忆 + 那条请求本身都要花 token |

**为什么是三回而不是一次通知**：压缩最怕落在话题中间 ——
真落中间了，摘要就是「我们正聊某件事，聊到一半」，那是最没用的一种。
**三回提醒的作用不是倒计时，是让 AI 把刀口挪到一段话说完的地方。**

### 🔴 还有三条判据，照着做能少踩三个坑

```
① 压缩是**闹钟**，不是存档动作
   它把 AI 叫醒去做一次消化 —— 存什么、存不存、几条，当场 AI 自己判断，
   可以一条都不存。⛔ 别让系统自动把细节灌进记忆库：
   记忆被自动写入撑坏，比丢一点细节严重得多。

② 那段「今天干了什么」存成**普通记忆**就好
   ⛔ 别给它一个「主线 / 大事件」的特殊身份 —— 每天灌一条日报进去，
   那个位置就被日报占满了，真正的主线反而没地方站。

③ 摘要要写成**能看出边界**的样子
   「00:10–00:40 聊了 X 这一段，逐字没了，结论是 Y」
   —— 压缩一定丢东西，**丢了却感觉不出来，AI 就会拿着一份有洞的记忆当完整的用，
   在洞上编一个听起来合理的答案**。能感觉到边界，它才不会编。
```

📌 **为什么这一半我们不替你写代码**：它要求「网关能把 AI 写的东西收回来」，
而怎么截住、往哪存，每家客户端都不一样；它还预设「一个窗口聊到死」，
而很多客户端自己就会压缩。**所以给的是判据和口子，不是实现。**

⛔ **这个外壳不替 AI 调 `breath()`。**
`自动贴.js` 里有一个「开窗第一轮把 breath 整段贴进 system」的函数，
这儿**故意不接**：「开口之前先 `breath()`」是 **AI 自己该伸的那只手**
（写在 [`docs/系统提示-中文.md`](../docs/系统提示-中文.md) 里）。
网关替它贴进去，它就不再是「自己想起来要睁眼」，而是「被人喂了一份摘要」——
那是两种完全不同的东西。真想要网关代劳，那个函数现成的，自己接一行就是。

## 两条路，挑一条

### ① 你已经有自己的网关 → 只拿模块

两个文件，都**零依赖**（只用 `fs` / `path` / 全局 `fetch`）、也**零 import 这个项目**：
`戳戳送达.js`（梦 / 发呆）和 `自动贴.js`（相关记忆提醒）。拷走，在转发逻辑里加两句：

```js
const 桥 = require("./戳戳送达.js");

// 转发之前调一次。它会**就地**改 messages（插一条 system），也可能什么都不做。
await 桥.贴一次({
  messages: body.messages,          // 会被就地修改
  requestId: "随便什么能对上日志的字符串",
  地址: "http://127.0.0.1:18002/mcp",   // Loci 在哪（/mcp 结尾，它自己会转成 REST 根）
  闲时阈值分钟: 210,                     // 她多久没说话才值得问一次
});
```

```js
const 自动贴 = require("./自动贴.js");

// 相关记忆提醒：**最后一步**。它自己不碰 messages，只把 patch 算出来还给你——
// 因为位置得离模型开口最近，要等你把请求体都组完了才推进去。
const 提醒 = await 自动贴.算相关记忆提醒({ messages: body.messages, requestId, 地址, 最低分: 50 });
if (提醒 && 提醒.patch) 自动贴.贴到真尾巴(body.messages, 提醒.patch);
```

**两处都会抛异常 —— 你要接住，然后照常转发。** 宁可这次没插上，也不能让人的对话卡住。

### ⚠️ 弱档为什么默认关着

强档 = 「上次 / 还记得 / 之前」这类词命中，**这个默认开着**。
弱档 = 「过滤掉应声词之后但凡有三个字以上的实质内容就放行」—— **默认关**。

不是因为它不准，是因为**它太宽**：日常说话几乎每句都过。
而一次 `recall` 要**好几秒**（实测 956 条的库要 5~7 秒，向量 + BM25 一起跑），
弱档开着 = 几乎每一轮聊天都卡那么久。

想全都要：`RELEVANCE_WEAK=1`。**先确认你的库 recall 有多快再开。**

📌 另一个已知简化：弱档那道过滤是「整句停用表 + 三字起」，
「嗯嗯好的」这种拼起来的应声话会漏过去。想做真判断，
换 `自动贴.js` 里 `弱档触发()` 那一个函数就行。

### 🔴 一个踩过的坑：超时给太少 = 这功能悄悄不工作

`算相关记忆提醒` 的超时原来写死 5 秒，而实测 recall 要 5~7 秒 ——
**于是它每次都超时中止，命中数恒为 0，一次都没成功过**。
而失败只进日志、聊天照常，所以**没有任何地方看得出来它没在工作**。

现在默认 12 秒（`RELEVANCE_TIMEOUT_MS` 可调）。
**你的库越大，recall 越慢，这个数要跟着涨。**
判断它有没有在工作，看日志里 `relevance_reminder_observed` 那条的
`injected` 和 `error` 两个字段 —— 别看聊天界面，界面上永远是正常的。

### ② 你没有网关 → 用这个外壳

```bash
LOCI_UPSTREAM=https://api.deepseek.com/v1 node gateway/server.js
```

然后把客户端的 `base_url` 指到 `http://127.0.0.1:3100/v1`。
API key 照常由客户端带 —— 这一层**原样转发，不存也不看**。

| 环境变量 | 默认 | 干什么 |
|---|---|---|
| `LOCI_UPSTREAM` | 无（必填） | 真正的模型在哪，OpenAI 兼容地址 |
| `PORT` | `3100` | 网关自己听哪个端口 |
| `LOCI_MCP` | `http://127.0.0.1:18002/mcp` | Loci 在哪 |
| `POKE_IDLE_MINUTES` | `210` | 她多久没说话，下一句才值得问一次 Loci |
| `RELEVANCE_MIN_SCORE` | `50` | 相关记忆提醒：多少分以上才算数 |
| `LOCI_RECENT_VIEW` | 关 | 设成 `1` 打开可选的近期记忆视图 |
| `RELEVANCE_TIMEOUT_MS` | `12000` | 相关记忆提醒等 recall 多久。**库越大要给越多** |
| `RELEVANCE_WEAK` | 关 | 设成 `1` 打开弱档触发（见下面那条警告） |
| `LOCI_GATEWAY_DATA` | `gateway/data` | 状态和日志落哪儿 |

## 三条它自己守的边界

- 🔴 **失败不挡聊天。** Loci 没起、超时、返回不是 JSON —— 全部照常转发，只记一行日志。
- 🔴 **只读多，写极少。** 它只碰 Loci 两个普通 REST 口：
  `GET /api/loci/poke`（纯读）· `POST /api/loci/dream/wake`（降级信号，幂等）。
  ⛔ **不碰 MCP 工具面。**
- 🔴 **不改内容，只加一行。** 插进去的是一条 system 消息，插在最新那条 user 之前。

## 为什么要有「闲时闸」

默认 210 分钟（3.5 小时）。**不是每条消息都问 Loci** —— 只有她长时间没说话之后
回来的**第一句**才问。

理由很实在：梦和发呆这类东西，是「她不在的时候系统自己长出来的」。
在她连着说话的空档里插一句「昨夜织了一个梦」，那不是提醒，是**插嘴**。

## 日志

一行一件事，落在 `gateway/data/logs/memory-actions.jsonl`。
状态（上次什么时候问的、要不要降级）落在 `gateway/data/state/poke-window.json`。
